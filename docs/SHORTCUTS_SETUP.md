# ショートカット設定手順

## 最初に知っておくこと

自動なのは「アプリの起動・切り替え時にファイルへ記録する部分」です。PWAへの取り込みは自分で行います。PWAをアプリの起動ごとに開く方式は、計測対象を切り替えてしまうため採用していません。

この手順はApple公式資料とアクション仕様に基づく手動構築用です。iPhone実機での全操作は未検証です。2026-10-30時点、iOS 27のオートメーション画面が改訂されています。英語公式で確認できた項目と、従来の日本語表記を併記します。「日付をフォーマット」は日本語iPhone資料で確認できました。「名前を設定」「ファイルを保存」の日本語名はAppleのMac版共通アクション説明で確認できましたが、iOS 27日本語の細かな選択欄名は未確認です。表示が違う場合はアクションの情報ボタンで内容を確認してください。存在を確認できないアクションを無理に置き換えないでください。

署名済み.shortcutファイル／iCloud共有リンクは、この環境では正規の作成・実機検証ができないため付属しません。

## A. 記録先を作る

1. iPhoneの「ファイル」を開く。
2. 「ブラウズ」→「iCloud Drive」を開く。
3. 「…」→「新規フォルダ」で CocoaTime を作る。あればその中に Events フォルダを作る。
4. 保存先を「iCloud Drive / CocoaTime / Events」として以降使う。
5. クラウドに置きたくない場合は「このiPhone内」で、保存アクションから選択できるフォルダを使う。この場合、別端末への同期はない。iCloudの容量・ネット接続が不足する場合もローカル保存が候補。どちらも実機で保存テストする。

iCloudを選ぶとログは自分のiCloudにも保存・同期されます。PWAのIndexedDBはそのiCloudフォルダとは別です。暗号化されていないCSVにはアプリIDと利用時刻が含まれるため共有フォルダにはしないでください。

## B. Cocoa Timeにアプリを登録

1. ホーム画面からCocoa Timeを開く。
2. 「アプリ管理」で表示名を入力。例：動画アプリ。
3. 記録IDを video_app にする。IDは半角英数字、ハイフン、アンダースコアのみ。
4. カテゴリ・1日の目標を設定して「追加する」。
5. アプリ一覧の「このアプリの記録設定 →」から、自分のID入りのCSVとファイル名を表示できます。以下の video_app は自分の記録IDに置き換える。アプリの表示名を変更してもIDは変えない。

例のアプリ名はコードには固定されていません。

## C. 起動を記録するショートカットを作る

「ショートカット」→新しいショートカット（＋）を作成し、名前を「CT video_app 開始」にします。以下を上から順に置きます。

### 1. 現在日時を用意

アクション検索で「日付」を選び、「現在の日付」を使います。この出力を以下では「取得日時」と呼びます。固定の日付を入力しないでください。別のアクション内で「現在の日付」変数を直接指定できる場合もありますが、ファイル名と内容で同じ時刻を使うため1回取得します。

### 2. 日付をフォーマット：ログ用

検索「日付をフォーマット」。入力欄をタップして「変数を選択」から1の「日付」の出力を選びます。文字列「取得日時」を直接打つのではなく、青い変数トークンを挿入します。

詳細を展開し、日付フォーマットを「カスタム」にします。フォーマット欄：

yyyy-MM-dd'T'HH:mm:ss.SSSXXX

結果例：2026-10-30T08:00:00.123+09:00

この出力を「記録時刻」と呼びます。必要なら変数トークンをタップして名前を変更すると区別しやすくなります。XXXはタイムゾーンで、+09:00を固定文字として偽装しません。暦は西暦に設定。時刻がずれている場合はiPhoneの「設定」→「一般」→「日付と時刻」を確認します。

### 3. 日付をフォーマット：ファイル名用

もう1つ「日付をフォーマット」を追加。入力を直前の文字列ではなく、1の「日付」に明示的に戻します。

カスタムのフォーマット：

yyyyMMdd-HHmmss-SSS

出力例：20261030-080000-123。この変数を「ファイル時刻」と呼びます。

### 4. テキスト：CSVを作る

「テキスト」アクションを追加し、2行で入力：

appId,type,at
video_app,open,[記録時刻]

[記録時刻]はその文字を入力せず、2の「日付をフォーマット」の出力を選びます。3のファイル用時刻を選ばないでください。実行後は例えば次の文字列です：

appId,type,at
video_app,open,2026-10-30T08:00:00.123+09:00

### 5. 名前を設定

検索「名前を設定」（英語 Set Name）。入力を4の「テキスト」の出力にし、名前を次にします。

video_app-open-[ファイル時刻].csv

[ファイル時刻]は3の出力変数です。例：video_app-open-20261030-080000-123.csv。既存のファイルを改名する「ファイルの名前を変更」と、生成した内容に名前を付ける操作を取り違えないでください。

もしこのアクションを見つけられない場合、次の「ファイルを保存」の保存先パス／サブパス指定欄が利用できれば、その欄で同じファイル名を指定できます。この欄の配置はiOS版によるため、存在する画面でのみ使ってください。どちらも見つからなければ、まず手動転記機能を利用し、表示されたアクションの画面を確認してから記録を構築します。

### 6. ファイルを保存

検索「ファイルを保存」（英語 Save File）。入力は5の名前付きの出力を選ぶ。保存先の選択欄でAのEventsフォルダを選びます。「保存先を尋ねる」等の確認オプションがある場合はオフにします。既存ファイルを上書きするオプションはオフにします。実行のたびにファイル選択画面が出る状態では自動記録になりません。

ファイル名にID・open・ミリ秒の日時を入れるため、通常の切り替えは別ファイルになります。ただし同一ミリ秒の再実行や時刻巻き戻しなどの衝突は完全排除できません。上書きを許可せず、保存エラーが出たら日時と重複したオートメーションを確認します。

### 7. 初回のテスト

再生ボタンで1回実行。初回のファイルアクセス許可を、自分で指定したフォルダについて許可します。「ファイル」で新しい.csvを開き、2行であること、日時が変数名ではなく実際の日時であること、openがあることを確認します。

ここでできたのはテストイベントです。本番に混ぜないよう別のテストフォルダへ移すか、取り込み前に対象から外してください。

## D. 終了用を作る

Cのショートカットを複製し、名前を「CT video_app 終了」に変更。

- CSVの open を close にする。
- ファイル名の -open- を -close- にする。
- 保存先は同じEventsフォルダ。
- ほかの設定は同じ。

「閉じた」はそのアプリから離れたイベントであり、プロセス終了を意味しません。

## E. オートメーションを関連付ける

### iOS 27の新しいエディタの場合

Apple英語版の現行ガイドでは、ショートカットを開き Edit → Automation でトリガーを追加します。日本語の該当項目は「編集」「オートメーション」に相当しますが、この版の全ラベルは未確認です。

1. Cの開始ショートカットを開き、編集画面のオートメーション追加を選ぶ。
2. Appトリガーを選び、対象アプリを1つだけ選ぶ。
3. 「開いている」／Is Openedに相当する条件を指定。終了も同時に選ばない。
4. Dの終了ショートカットにも同じアプリを指定し、「閉じている」／Is Closedに相当する条件を指定。
5. 編集画面の情報（ⓘ）→Privacyに、Allow Running When Lockedがある場合は、自動実行を許可するため設定を確認する。日本語表示は端末で確認。個々のファイル操作の許可は別途必要。
6. 即時実行と確認後実行の選択肢が表示される場合は、確認なしの設定を選ぶ。

### 「オートメーション」タブから作る従来の画面の場合

1. 「ショートカット」→「オートメーション」→「＋」（初回は新しいオートメーション）を選ぶ。
2. 「App」→「選択」→対象アプリ1つ→「完了」。
3. 開始用では「開いている」だけ、終了用では「閉じている」だけを選択。
4. 「すぐに実行」が表示される場合はそれを選ぶ。旧画面の「実行の前に尋ねる」がある場合はオフ→「尋ねない」。
5. 「次へ」→既存ショートカットとして開始用または終了用を選ぶ。直接選択する画面がない場合は「ショートカットを実行」アクションに、該当ショートカットを指定。
6. 完了して保存し、開始用・終了用の両方を作る。

対象アプリが増えたらB〜Eを繰り返します。複数アプリを1つのトリガーにまとめると、どのアプリから離れたかの識別が曖昧になるため、開始・終了各1本をアプリごとに用意します。「現在のアプリを取得」は離れたアプリの識別に使用しません。

## F. PWAで取り込む（日常操作）

1. 対象アプリを30〜60秒使う。
2. ホーム画面や別アプリへ切り替える。
3. 「ファイル」→Eventsにopen/closeの2ファイルが作られたことを確認。
4. Cocoa Time→「その他」→「設定」→ファイル選択。
5. 「ブラウズ」→Eventsを開き、取り込むCSVを複数選択して開く。ファイル選択画面の複数選択操作はiOS版に依存します。
6. 新規件数・重複件数を確認し「この内容を反映する」。
7. 「履歴」でペア推定が約1分になっていることを確認。
8. 毎日または数日に一度、新しいファイルをまとめて選択。重複して選んでも appId/type/日時 が一致すれば1件に統合されます。1回20MB・1000ファイルまで。

1イベント1ファイルは初期構築とデータ衝突の回避を優先した方式です。ファイル数が増えるため、取り込み後のCSVを週別の保管フォルダに移すと選択しやすくなります。すぐに元ログを消さず、JSONバックアップの保存を確認してください。

## G. エラーを見つける

|症状|確認すること|
|---|---|
|ファイルが増えない|トリガー対象、オートメーション有効化、自動実行、保存フォルダ、権限、空き容量|
|毎回保存画面が開く|ファイル保存の「尋ねる」設定、固定フォルダの指定|
|拡張子が.txt|内容がCSVなら.txtも取り込める。名前を設定の拡張子を確認|
|日時形式のエラー|2の出力をCSVへ渡しているか、XXXとTと秒の指定、西暦|
|「終了イベントなし」|終了オートメーションが動いたか。使用中の可能性もある。推測で終了を足さない|
|「起動記録がない終了」|開始用の失敗・選択漏れ・時刻変更を確認|
|何時間も使った扱い|ロック等の終了欠落。確認上限を超えた分は除外される。標準画面から手動転記|
|取り込み後も今日が未記録|ファイルの日付と日本時間を確認。古いファイルなら過去日の分析を見る|

保存失敗を自動で捕捉・再送する仕組みや、全実行が成功したことの証明は実装していません。必要ならテスト中だけ、保存の後に「通知を表示」を追加して成功経路の到達を確認してください。成功通知がないことだけで原因は特定できません。実行エラーはショートカット側の表示を確認します。

## H. 最初の実機検証

以下を各3回程度試し、日時とファイルの有無を確認してください。

- 起動→別アプリへ切り替え。
- 起動→画面ロック→30秒後に解除。
- 起動→Appスイッチャーから強制終了。
- 2つの記録対象アプリをすばやく切り替え。
- 機内モード・低電力モード・iCloud未同期。
- 再起動後の初回ロック解除と実行。

ロック中の経過時間が含まれたりイベントが欠けるなら、その使い方のログは信頼できません。該当アプリ・日の標準スクリーンタイムを「履歴」で手動転記し、推定値を置き換えてください。
