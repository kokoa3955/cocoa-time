# WindowsとiPhoneへの導入

## 今回の納品状態

ソース、ビルド済みdist、設定手順、テストをZIPにまとめています。ユーザーが新規の公開リポジトリ kokoa3955/cocoa-time を作成し、配信用ファイルを配置しました。GitHub Pagesの有効化とiPhone実機での確認は別の工程です。

PWAはApp Storeアプリではありません。iOSアプリの署名・App Store審査・Macは不要です。iPhoneにZIPやindex.htmlを保存してタップするだけでは、サービスワーカー付きPWAとして導入できません。

## 1. Windowsで展開

1. cocoa-time-v1.0.1.zip をダウンロード。
2. エクスプローラーで右クリック→「すべて展開」。
3. 展開先のcocoa-timeフォルダを開く。
4. README.md等はメモ帳やVS Codeで読めます。distはブラウザ配信用の完成ファイルです。

## 2. PCで動作確認する（公開前）

Node.js 24以降を公式サイト https://nodejs.org/ からインストールします。LTSの24以上を選択。インストール後、新しいPowerShellを開きます。

cocoa-timeフォルダ内で右クリックして「ターミナルで開く」。

node --version
npm.cmd ci
npm.cmd run check
npm.cmd test
npm.cmd run build
node scripts/serve.mjs

最後に表示される http://localhost:8080/ をPCのブラウザで開きます。終了はCtrl+C。PowerShellの実行ポリシーに干渉しないよう、npm.cmdを使っています。セキュリティ設定を緩める必要はありません。

ビルド済みdistの確認だけならnpm ci以降の再ビルドは不要で、Node.jsを入れてserve.mjsを実行できます。このPC用サーバーは127.0.0.1だけで待ち受けます。iPhoneからはアクセスできず、PCの確認用です。

## 3. iPhone用のHTTPS配信を準備

無料のGitHub Pagesが候補です。無料プランでの一般的な構成は公開リポジトリです。リポジトリをPrivateにしただけでPagesも本人限定になるわけではありません。

この選択では「アプリ本体のコードとURL」が公開されます。利用履歴はブラウザ内に保存され、公開リポジトリへ自動送信する処理はありません。しかしコードも他の人に見せたくない場合、この方法は選ばないでください。本人限定ホスティングのサービス・契約条件を別途検討する必要があります。

以下は、配信先を確認・再設定するための手順です。公開リポジトリの作成と配信用ファイルの配置は済んでいます。

### GitHubの画面で公開する場合

1. 作成済みリポジトリ https://github.com/kokoa3955/cocoa-time を開く。
2. リポジトリの表示範囲がPublicであることを確認。
3. mainブランチのルートにindex.htmlなどの配信用ファイルがあることを確認。
4. 更新時だけ、distフォルダの中身を同じ構成で差し替える。個人のログやバックアップはアップロードしない。
5. 変更時はコミットしてからPagesの更新を待つ。
6. Settings→Pages→Build and deployment→SourceをDeploy from a branchにする。
7. Branchをmain、フォルダを/(root)にしてSave。
8. GitHubが表示するサイトURLをコピー。末尾のリポジトリ名を含むURLで開く。
9. 反映後、iPhoneのSafariでそのURLを開く。

バックアップJSON、自分のCSV、Eventsフォルダ、アカウント情報はアップロードしないでください。ソース管理も行う場合はZIPのプロジェクトを別途Gitで管理でき、ビルド成果物だけを配信します。必要なら引き継ぎ時に専用のPagesワークフローを追加してください。

GitHub公式：
https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages
https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 4. ホーム画面に追加

1. iPhoneのSafariで配信URLを開く。アプリ内ブラウザではなくSafariを使う。
2. ページメニュー→「共有」（レイアウトによっては共有ボタンが直接表示）。
3. 「ホーム画面に追加」を選ぶ。なければ共有アクション一覧の編集で追加。
4. 「ウェブアプリとして開く」が表示される場合はオン。
5. 「追加」。
6. ホーム画面のCocoa Timeから開き直す。以後ここを日常の利用場所にする。
7. 「設定」で永続保存をリクエスト。拒否されても使用できますが、JSONバックアップを続けてください。

Apple公式： https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/27/ios/27

Safariで入力した記録がホーム画面側に引き継がれない場合は、Safari側でJSONバックアップし、ホーム画面側で読み込んでください。別URL・別ブラウザ・別端末の記録は自動同期しません。

## 5. 初回記録

1. 「アプリ管理」で記録するアプリを1つ追加。
2. SHORTCUTS_SETUP.mdに沿って開始・終了の記録を作る。
3. 動作テスト後に「設定」からCSVを取り込む。
4. SCREEN_TIME_SETUP.mdに沿って標準の使用制限を設定。
5. 初回のJSONバックアップを「ファイル」に保存。

最初から自動記録の設定が難しい場合も、標準スクリーンタイムの値を「履歴」で手動転記して日・週・月の分析ができます。

## 6. 毎日の操作

- 朝：新しいログをファイル選択して取り込む。ホームで前日・今日を確認。
- 勉強：勉強開始、OS側の集中モード等を別途オン、終わったら勉強終了。
- 週1回程度：JSONを保存。バックアップは平文の個人情報なので保管先に注意。

記録対象のアプリを開くたびにPWAを開く必要はありません。PCを起動し続ける必要もありません。配信サービスが停止しキャッシュも消えた場合には、再配信が必要になります。

## 7. 更新

1. まずJSONバックアップを保存。
2. 修正版のdist全体を同じ配信先へアップロード。
3. PWAの「設定」→「アプリの更新を確認」。
4. 更新がある場合に確認して再読み込み。
5. 記録があることを確認。

ビルドは内容ハッシュ付きキャッシュを作ります。更新の全ファイル取得が成功するまで旧版を保持し、利用者の更新操作で切り替えます。開いたままの別タブがある場合は閉じてください。キャッシュを消すためにサイトデータを丸ごと削除すると、記録も失う可能性があります。

## 8. オフライン確認

HTTPSで一度開いてオフライン用ファイルの取得を完了させた後、機内モードでホーム画面から起動。ホーム、分析、手動入力、勉強開始終了、同梱手順書の閲覧ができるか確認します。iCloud上だけにある未ダウンロードのCSVは、オフラインで選択できないことがあります。
