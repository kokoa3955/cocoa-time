## 実装済み

READMEに列挙する8画面とローカルデータ処理。詳細なモデルはDATA_MODEL.md。主なポリシーは「不足した終了を捏造しない」「手動値はアプリ・日単位で優先」「未記録日はゼロと区別」「標準制限を操作できるように見せない」。UIに固定のアプリ一覧やデモ初期データはありません。

## 設計判断

- Windows・無料・Macなし・審査なしを優先して静的PWA。
- Reactや大規模グラフライブラリを使わず、画面関数と共通チャート部品で構成。純粋集計と永続化は別モジュール。
- 1イベント1CSVは共有ファイルの同時追記競合を避けるため。ファイル数が多くなるという使いやすさの課題を残す。
- PWAを毎イベントURLで起動する方式は利用計測を妨げるため不採用。
- バックアップ復元は、入力全体を検証後に1つのIDBトランザクションで置換。revisionで複数タブの上書きを防ぐ。
- CSP、動的文字列のエスケープ、ID制限、ファイル上限、日時検証を実施。
- Service Workerは全静的ファイルのプリキャッシュ。利用者が更新を選ぶまで待機。内容ハッシュで版管理。

## 仕様調査でわかった更新点

iOS 27の日本語スクリーンタイム資料に「許容時間」「スクリーンタイムのスケジュール」があります。従来の「App使用時間の制限」「休止時間」だけを案内しないでください。iOS 27のショートカットはエディタ内のオートメーションが公式英語資料にあり、全日本語ラベルは未確認。実機でこの差を最優先で埋めてください。

## 既知の制約・改善候補

- モバイルで細かい時間帯や月の棒は狭い。タップ可能だが、拡大操作・表形式の詳細ビューを加える余地がある。
- 大量取り込みはメインスレッドで処理。20kのLinux試験は通るがiPhoneの100k性能は未確認。必要ならWeb Worker化と日別キャッシュ。
- 1つのIDBレコードに状態を保存。将来はイベントストアを分割し、インデックス・マイグレーションを導入可能。
- 勉強記録は経過時間のみ。終了忘れを除外する操作やメモ・中断操作は拡張候補。
- 同一オリジンに複数配置する運用はIDB領域を共有するため避ける。
- iOSのショートカット側で、複数ログを1回の手動書き出しにまとめる正規フローを実機検証して追加すると日常負担を減らせる。
- 完全に本人限定の配信を希望する場合は、認証付きホスティングの無料条件・オフライン時の認証・更新を別途設計。公開GitHub Pagesを本人限定と呼ばない。

## 検証コマンド

npm ci
npm run check
npm test
npm run build
node scripts/serve.mjs

buildはdistを作り直します。distをカレントディレクトリとして配信するプレビューサービスでは、ビルド後にプレビューの再起動が必要な場合があります。納品ZIPにテスト用ブラウザの保存データは含めません。

## ネイティブ移行するなら

Mac/Xcode・Apple Developer Program・必要なFamily Controls権限・各拡張の署名条件を再調査する。TypeScriptのイベント／日別手動値／勉強区間モデルを移行仕様として再利用可能。標準APIから得る実測・匿名トークンと、現在の任意appIdの対応を自動取得できると仮定しない。推定とOS由来の新しいデータソースを区別するスキーマ版を作る。
